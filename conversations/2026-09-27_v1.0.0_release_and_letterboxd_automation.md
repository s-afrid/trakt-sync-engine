## 🎯 1. Mission & Core Function Specification Contract

The primary purpose of the Trakt Sync Engine is to unify watch history, anime episode progress, and movie diary entries across **Trakt.tv**, **MyAnimeList (MAL)**, and **Letterboxd** under a strict 4-pillar contract:

1. **15-Minute Cycle**: The background sync daemon checks Trakt activity on a recurring 15-minute schedule.
2. **Quiet Sleep (Smart Diffing)**: If no new movies or anime episodes were watched on Trakt since the last cycle, it remains completely quiet, consumes 0% active CPU, and never opens browser windows.
3. **Automated Anime Sync (Trakt ➔ MyAnimeList)**: Whenever an anime episode or series is watched on Trakt, the engine automatically updates the watched episode count and marks the series status as 'completed' on MyAnimeList (with smart finale and out-of-order watch detection).
4. **Automated Movie Sync (Trakt ➔ Letterboxd)**: Whenever a movie is watched/scrobbled on Trakt, the engine automatically generates the verified CSV (merging real-time history scrobbles with TMDB/IMDb IDs) and auto-imports/confirms it into Letterboxd via Playwright session persistence without manual interaction.

## 🔍 2. Key Challenges & Engineering Breakthroughs

### A. Cloudflare Turnstile & Stealth Session Persistence
- **Problem**: Letterboxd enforces Cloudflare Turnstile bot challenges on both `/sign-in/` and `/import/csv/`. Automated Playwright logins frequently triggered interactive verification loops.
- **Solution**:
  - Implemented anti-detection stealth evasion flags (`--disable-blink-features=AutomationControlled`, desktop user agent, real viewport).
  - Built an automated Turnstile solver in `scripts/automate_letterboxd_upload.py` that locates Turnstile iframes and performs coordinate/checkbox mouse clicks.
  - Implemented session persistence using [Cookie-Editor](https://cookie-editor.com/) exports. Saved session cookies in `.letterboxd_session.json` and passed via GitHub Secret `LETTERBOXD_SESSION_JSON`.
  - Configured `scripts/automate_letterboxd_upload.py` to prioritize `LETTERBOXD_SESSION_JSON` from environment over stale cached files from GitHub Actions runners.

### B. Playwright Auto-Confirmation Timeout Fix (`element is not visible`)
- **Problem**: During CSV auto-import on Letterboxd, the runner timed out waiting for the confirmation button with:
  `Locator.scroll_into_view_if_needed: Timeout 29992ms exceeded. element is not visible`
- **Root Cause**: The selector list included broad classes like `.button.-green` and `input[type='submit']`. Playwright's `.first` selected a hidden element inside Letterboxd's header/modal navigation (`display: none`). Calling `scroll_into_view_if_needed()` on a hidden element blocked Playwright until the 30-second timeout.
- **Solution**:
  - Replaced generic selectors with `match_ready_selectors` (`a.save-users-imported-imdb-history`, `a.submit-matched-films`, `form.import-step-2`, `.import-matches-container`, `strong:has-text('Matching complete')`).
  - Implemented **Strategy 1 (Direct DOM Dispatch)**: Uses `page.evaluate()` to auto-close blocking modal overlays (`dialog.turnstile-dialog`), find visible candidates, scroll via `el.scrollIntoView()`, and trigger `.click()` directly in the browser runtime.
  - Implemented **Strategy 2 (Safe Playwright Fallback)**: Uses `:visible` pseudo-class filter with a safe non-blocking 3s timeout for `scroll_into_view_if_needed` and forced click.
  - Verified in runner:
    `✅ Clicked final import button via direct DOM dispatch (primary_class: 'Saving…')!`
    `[2026-09-27 17:25:46] ✅ State saved: 25 movies tracked.`

### C. Live Real-Time Letterboxd Diary Verification
- **Problem**: In the web application's 24h Activity tab, *Bigil (2019)* was displaying as `PENDING IMPORT` even after it had been successfully imported into Letterboxd.
- **Root Cause**: `app/api/activity/24h/route.ts` was only reading from local database logs (`syncLogs`) recorded during a prior manual reverse sync rather than checking Letterboxd's live state.
- **Solution**:
  - Updated `lib/clients/letterboxd.ts` (`fetchUserRss`) to fetch `https://letterboxd.com/<username>/rss/` with `cache: 'no-store'` (real-time) and extract `tmdb:movieId` alongside `filmTitle` and `filmYear`.
  - Updated `app/api/activity/24h/route.ts` to live-query Letterboxd's public RSS feed on every refresh, cross-referencing movies by title and TMDB ID.
  - Verified that *Bigil* (TMDB 563309) is present in the feed, enabling immediate real-time display of `AUTO-IMPORTED (Confirmed in Letterboxd Diary)`.

### D. GitHub Actions Telemetry & Two-Way Sync Reporting
- **Question**: Can the Vercel-hosted web app access the execution output of GitHub Actions?
- **Solution**:
  1. **Pull Model (`/api/github/actions`)**: Queries GitHub's REST API for `s-afrid/trakt-sync-engine` workflow runs, extracting run number, status (`completed`, `in_progress`), conclusion (`success`, `failure`), duration, and log URL. Connected to the **Background Sync** stat card in `components/Activity24hTab.tsx`.
  2. **Push Model (`/api/sync/report`)**: At the end of `run_sync_cycle` in `scripts/automate_letterboxd_upload.py`, the script posts execution metadata (synced count, titles preview, runtime, run ID) directly to Vercel, persisting it in the Neon Postgres `syncLogs` table.

## 🍪 4. Letterboxd Session Management & Fail-Safe Renewal

When Letterboxd session cookies expire (Cloudflare or login required):

1. **Export**: Open [letterboxd.com](https://letterboxd.com) in browser while logged in ➔ Click [Cookie-Editor](https://cookie-editor.com/) ➔ **Export** ➔ **Export as JSON**.
2. **Apply**:
   - **GitHub Cloud**: Go to repo ➔ **Settings** ➔ **Secrets and variables** ➔ **Actions** ➔ update `LETTERBOXD_SESSION_JSON`.
   - **Web App**: Go to Live Activity tab ➔ click **Update Session** ➔ paste JSON.
